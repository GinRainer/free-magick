# Модуль «Свободная Магия» для Foundry VTT (Daggerheart / Foundryborne)

Технический план модуля на основе документа «Конструктор Свободной Магии».
Целевая система: **Foundryborne/daggerheart**, Foundry **v14**.

---

## 1. Что модуль делает (Scope v1)

- Даёт игроку отдельное окно — **Круг Свободной Магии** — где он визуально раскладывает Жетоны по секторам (Урон, Дистанция, Область, Целеуказание, Продолжительность, Цена и т.д.) и включает нужные Модификаторы.
- Считает суммарную стоимость в жетонах и сверяет с доступным запасом.
- Учитывает Освоение/Мастерство модификаторов (переключается прямо в окне).
- Отправляет в чат оформленную карточку заклинания: секторы/тиры, модификаторы, потраченные жетоны, поле-заглушка для категории Сложности (её вписывает ГМ вручную, автоматического расчёта нет — сознательное решение по вашему запросу).
- Показывает панель на листе персонажа: текущий запас Жетонов по Путям, разблокированные Модификаторы и их степень Освоения.
- Автоматически увеличивает запас Жетонов Пути, когда через Skill Tree разблокируется соответствующий скилл.

**Сознательно не входит в v1** (перенесено в поздние фазы, требует отдельного обсуждения): автоматический расчёт Сложности/Отката, Ритуал как многошаговый процесс с проверками, автоматизация Стойкости, банк Магического Фона у ГМа, разница Магических Кругов.

## 2. Типы данных

### 2.1 Item: «Путь Магии» (`free-magic.path`)
Новый саб-тайп Item (по аналогии с тем, как Hotpot добавляет саб-тайп `ingredient`).

Поля:
- `direction` — выбор: Усиление / Осознание / Контроль / Воплощение / Изменение / Дар
- `rank` — число (ранг направления)
- `tokensGranted` — вычисляется = rank (или своя формула)

Сортируется на листе персонажа в собственную секцию, отдельно от обычных «Особенностей» — как Ingredient у Hotpot.

### 2.2 ~~Item: «Модификатор Свободной Магии» (`free-magic.modifier`)~~ — заменено разделом 12.1

Изначальный план: один саб-тайп с чекбоксами `proficiency`/`mastery`, переключаемыми в окне Круга. По факту решено иначе — тир (Базовое/Освоение/Мастерство) фиксируется прямо в предмете при создании (ты делаешь три разных Item нужного тира и раскладываешь по дереву Skill Tree, а не один предмет с переключателями). Актуальная модель — раздел 12.1, Item-тип `free-magic.attribute`.

### 2.3 ~~Domain Card, новый саб-тайп «Знание» (`free-magic.knowledge`)~~ — отменено

Идея была нужна, чтобы карта Домена «разблокировала» конкретный Item-модификатор. С переходом на прямые Item-типы «Тэг»/«Атрибут» (раздел 12.1), которые раскладываются по Skill Tree напрямую, отдельный тип карты не нужен — отменено без замены.

### 2.4 Actor flags
```
flags.free-magic.directions: {
  usilenie: { tokensSpent: 0 },
  osoznanie: { tokensSpent: 0 },
  kontrol: { tokensSpent: 0 },
  voplochenie: { tokensSpent: 0 },
  izmenenie: { tokensSpent: 0 },
  dar: { tokensSpent: 0 }
}
```
Сам запас (`tokensGranted`) не дублируется во flags — берётся динамически суммированием всех Items `free-magic.path` этого актора с нужным `direction`. Это исключает рассинхронизацию: источник истины — Items.

## 3. Интеграция со Skill Tree (theripper93)

Skill Tree создаёт реальный Item на акторе при разблокировке скилла (`createItem`). План:

1. При наполнении дерева каждый разблокируемый скилл, отвечающий за Путь Магии, делается Item'ом типа `free-magic.path` с проставленным `direction` и `rank`.
2. Модуль вешает хук:
```js
Hooks.on("createItem", (item, options, userId) => {
  if (item.type !== "free-magic.path") return;
  // пересчитать доступный запас Жетонов у актора (просто вызывает рендер панели/приложения)
});
```
3. Никакой ручной синхронизации не требуется — панель на листе и окно Круга всегда читают Items «на лету».

Отдельная инструкция по маркировке скиллов будет дана на этапе наполнения дерева (когда дойдём до контента).

## 4. Интерфейс

### 4.1 Панель на листе персонажа
Новая вкладка/секция «Свободная Магия»:
- Список Путей с текущим запасом (сумма рангов Items) и потраченным на данный момент (0, если не открыт Круг).
- Список разблокированных Модификаторов с индикатором Освоение/Мастерство.
- Кнопка «Открыть Круг».

### 4.2 Окно «Круг Свободной Магии» (ApplicationV2)

Фактическая реализация (v0.1–v0.3) — три колонки:

- **Слева** — панель «Мои жетоны»: шесть Путей (запас/потрачено), клик по Пути делает его «активной кистью».
- **По центру** — радиальный SVG-Круг: пять секторов Траты (Урон, Дистанция, Область, Целеуказание, Продолжительность), каждый разбит на 4 кольца (I–IV) + нейтральный тир 0 в центре (со штриховкой, чтобы не путать с пустыми кольцами). Клик красит кольцо цветом и буквой активного Пути, тир выставляется последовательно. Кнопка сверху переключает эту колонку на страницу **«Докупить жетоны»** — список параметров Начисления (Скорость, Цена, Жертва, Ресурс) с кнопками уровня 0–IV и текстовым описанием выбранного уровня (не второй Круг, а отдельная простая форма).
- **Справа** — список Модификаторов (чекбоксы), поле «Корректировка ГМа», итоговые суммы, поле намерения и кнопка «Сотворить».

Счётчик «Итого чистыми» всегда на виду. Запас каждого Пути (пока — ручной ввод во флаге актора, до готовности Item type в v0.5) не даёт уйти в минус — при нехватке клик по кольцу блокируется с уведомлением.

Ниже — визуальный макет ранней версии интерфейса (до перехода на три колонки и физические токены — актуальный вид уже несколько отличается по компоновке, суть механики та же).

## 6. Банк Магического Фона

### Обновлено в v0.11 — привязка к Сцене
Изначальное решение (v0.1) было НЕ привязывать Фон к Сцене — отдельный мировой счётчик, которым управляет только ГМ вручную. По факту это решение пересмотрено: теперь ГМ может либо оставить Фон глобальным, либо привязать его к конкретной Сцене (у каждой Сцены — свой набор данных во флаге самого документа Scene). Игроки видят Фон той Сцены, которую сейчас показывает их канвас (`canvas.scene`), с прозрачным откатом на глобальный, если для текущей Сцены ничего не настроено. См. `scripts/bank.js` — `getSceneBankData`/`setSceneBankData`.

### Хранение
```js
game.settings.register("free-magic", "backgroundBankValue", { scope: "world", config: false, type: Number, default: 0 });   // глобальный откат, видит только ГМ
game.settings.register("free-magic", "backgroundBankMax", { scope: "world", config: false, type: Number, default: 50 });
game.settings.register("free-magic", "backgroundBankUnstableLock", { scope: "world", config: false, type: Boolean, default: false });
// Для конкретной Сцены — тот же набор трёх полей, но во флаге: scene.flags.free-magic.bank = { value, max, lock }
```
Три независимых поля на каждый контекст (глобальный или конкретная Сцена): точное число (только ГМ), автоматическое **Состояние** (% от максимума — см. `computeBankStateKey`) и **Уровень** (по абсолютному числу: Высокий 25+ / Обычный 10–25 / Низкий <10). Игроки видят Состояние и Уровень, не видят точное число.

### Окно настройки (переработано в v0.11)
Отдельная `ApplicationV2` (`FreeMagicBankConfig`, `scripts/bank-config-app.js`) — теперь с выбором Сцены (или «Глобально») в самом верху, дальше числовые поля для точного значения/максимума конкретно этого контекста, авто-Состояние/Уровень для сверки, и отдельный раздел быстрой настройки Максимума Цены по всем персонажам игроков сразу. Доступна из блока Банка на странице «Получить Токены Маны» (кнопка «⚙ Настроить», видна только ГМу) и напрямую макросом `new FreeMagic.FreeMagicBankConfig().render(true)`.

### Отображение в окне Круга
- **ГМ** видит панель с точным числом и полем для правки, плюс авто-Состояние/Уровень для текущей (по канвасу) Сцены игрока, чьё окно Круга открыто.
- **Игроки** видят только Состояние и Уровень, без точного числа.

### Взятие жетонов игроком (реализовано в v0.4, дополнено в v0.11 поддержкой Сцен)
- Кнопка «Взять 1 из Банка» — на странице «Получить Токены Маны».
- Полученный жетон уходит не в абстрактный «личный пул», а конкретной строкой **«Дикие Токены»** в панель «Мои Токены Маны» слева — доступен как обычная кисть для закрашивания колец Круга.
- Технический нюанс: у игроков обычно нет прав менять мировые настройки/флаги Сцены Foundry напрямую. Если жетон берёт не-ГМ, модуль отправляет запрос через `game.socket` (вместе с ID актуальной для игрока Сцены), и уже ГМ-клиент (если он в сети) списывает жетон. Это оптимистичное обновление без подтверждения — если ГМа нет в сессии, счётчик не уменьшится, хотя у игрока Дикий Токен уже появится.
- Лимит по Магическому Кругу персонажа **пока не реализован** — сейчас проверяется только фиксированная тройка за сборку и то, что в Банке вообще что-то есть.
- Дикие Токены не персистентны — обнуляются при следующем открытии окна.

### 6.1 Токены Маны (обобщённый пул, реализовано в v0.4)
Изначально (v0.1–v0.3) жетоны от Докупки и от «дающих» модификаторов просто вычитались из абстрактной формулы стоимости. С v0.4 это заменено на честный пул: результат уходит строкой **«Токены Маны»** в панель слева — не привязан к конкретному Пути, доступен как кисть, физически размещается на кольцах Круга (иконка капли). Считается на лету: сумма выбранных тиров Докупки + сумма модификаторов с отрицательной стоимостью + отрицательная часть Корректировки ГМа. Не персистентен — обнуляется при следующем открытии окна.

## 7. Пути Магии: цветовая маркировка и панель токенов (в стиле Paper Doll)

Paper Doll (theripper93) реализован как выезжающая панель-«вкладка» на краю листа персонажа: маленький язычок сбоку, при клике выезжает полноценная панель поверх листа. Берём этот же паттерн интерфейса для панели Путей — но с содержимым не «экипировка», а шесть Путей Магии с их запасом токенов.

### 7.1 Панель Путей (выезжающая вкладка) — реализовано в v0.9

Вертикальная вкладка у левого края листа персонажа (`scripts/sheet-panel.js`), внедряется тем же приёмом, что и кнопка открытия Круга — подписка на несколько вероятных имён рендер-хуков листа (см. раздел про диагностику в v0.1). Панель добавляется как прямой потомок корневого DOM-узла листа, поэтому позиционирование `position:absolute` считается от границ самого листа и корректно едет вместе с ним при перетаскивании/ресайзе.

Секция «Токены Путей» показывает для каждого из шести Путей три числа:
- **База** — редактируемое поле, тот же флаг актора `free-magic.pathPools`, что раньше редактировался только внутри окна Круга (единый источник данных, вынесен в более удобное постоянное место).
- **Бонус от предметов** — сумма всех Items на акторе, у которых выставлены флаги `flags.free-magic.direction` (ключ Пути) и `flags.free-magic.rank` (число). Это универсальный механизм на флагах, а не отдельный зарегистрированный саб-тайп Item (более безопасный путь без изменения схемы данных чужой системы) — работает одинаково для:
  - бонус-предметов, создаваемых кнопкой «+ Бонус-предмет» прямо в панели (открывает `DialogV2` с полями название/величина);
  - любого другого Item, если вручную проставить те же флаги;
  - предметов, приходящих от Skill Tree при разблокировке скилла — если сам скилл в дереве помечен теми же флагами, авто-подхватывается без отдельного кода интеграции.
- **Итого** — база + бонус, именно это число видит окно Круга (`scripts/paths.js#getItemBonusByPath` — общий модуль, импортируется и Кругом, и панелью, чтобы визуальный язык и логика подсчёта не расходились).

### 7.1.1 Прежний план vs фактическая реализация
Изначально планировался Item type `free-magic.path` как отдельный зарегистрированный саб-тайп. По факту реализован более простой и безопасный вариант — генерический механизм на флагах поверх обычного типа `feature` (тип определяется динамически из активной системы, не хардкодится). Панель внутри Круга (палитра активной кисти, см. 7.3) сохранена как отдельная лёгкая версия для быстрого выбора во время сборки заклинания — полноценное управление (база + бонус-предметы) теперь живёт в постоянной панели листа персонажа.

### 7.2 Цветовая маркировка Путей
Каждому Пути присваивается свой цвет (используется единая палитра и в панели, и в Круге, и в чат-карточке):

| Путь | Цвет |
|---|---|
| Усиление | Purple |
| Осознание | Teal |
| Контроль | Coral |
| Воплощение | Pink |
| Изменение | Amber |
| Дар | Blue |

### 7.3 Как это работает в Круге
Раньше кольцо сектора просто заполнялось при клике. Теперь:
1. Игрок выбирает **активный Путь** в панели (клик по строке Пути — как выбор кисти).
2. Клик по кольцу сектора закрашивает его цветом выбранного Пути и списывает 1 токен из запаса этого Пути.
3. Если в одном секторе набор колец включает жетоны разных Путей — сектор визуально отображается сегментами разных цветов (кольцо разбивается по вложенным токенам, а не заливается одним цветом).
4. Это даёт основу для будущих интеракций: например, модификатор «Мистическая адаптивность» (трансформация жетона одного Пути в другой) может явно указывать, с какого кольца/Пути игрок трансформирует токен, а Domain Card «Знание» — проверять, жетоны какого Пути формируют заклинание.

### 7.4 Данные
Распределение по секторам хранится не просто как число тира, а как разбивка по Путям:
```js
// временное состояние окна Круга (не персистентное — обнуляется при "Сотворить")
{
  urn: { tier: 3, allocations: { voplochenie: 2, usilenie: 1 } },
  distance: { tier: 1, allocations: { osoznanie: 1 } }
}
```
Это же используется при генерации чат-карточки — можно показать не только тиры, но и то, какие Пути формировали заклинание (что отражает нарративный принцип документа: «жетоны направляют описание, а не просто числа»).

## 8. Магическая Стойкость

Реализуется по той же логике, что и Очки Брони в самой системе Foundryborne — без изменения схемы актора.

### Почему это безопасно и реалистично
В системе Items уже умеют нести встроенный **Resource** (значение/максимум с кликабельными ячейками — именно так у Foundryborne устроены Очки Брони и ресурсные Карты Домена вроде Rally). Это готовый, поддерживаемый системой механизм — модулю не нужно трогать data model актора или городить собственный трекер ячеек.

### Реализация
1. Стойкость — Item (feature/loadout-подобный саб-тайп) с прикреплённым Resource: `value` / `max`.
2. Кладётся в инвентарь персонажа как обычный предмет — он автоматически получает тот же кликабельный трекер ячеек, что и Броня, без дополнительного кода на рендер.
3. `max` растёт от прокачки (аналогично Путям — можно точно так же завязать на Skill Tree через `createItem`, если понадобится).

### Логика применения (v1 — вручную)
- Цель заклинания вручную кликает ячейки своей Стойкости, чтобы снизить/аннулировать эффект — так же, как сейчас работает Броня.
- Автоматизацию (кнопка «Потратить Стойкость» прямо в чат-карточке заклинания, которая программно списывает `resource.value` у цели через `item.update()`) можно добавить отдельной фазой позже — это не блокирует базовую версию.

### Отличие от Брони
Отдельный Item, не путается с физической Бронёй — Стойкость реагирует конкретно на магические эффекты (по формулировке из документа), поэтому это самостоятельный ресурс, а не расширение существующего.

### ⟳ Пересмотрено — см. раздел 12.2
План выше (Item со встроенным Resource) заменён на кастомный ресурс актора через `CONFIG.DH.RESOURCE.character.custom` — та же инфраструктура, что и Ресурс Элементов (раздел 11.6), плюс конкретика по выбору «Урон или Мистический Эффект» при трате. Раздел оставлен как есть для истории решения (Item-подход тоже был бы рабочим, но раз всё равно поднимаем инфраструктуру кастомных ресурсов под Элементы — логичнее унифицировать).

## 9. Ручная корректировка ГМа (закрывает Ритуал и разницу Кругов)

Осознанное решение: не автоматизировать Ритуал и разницу Магических Кругов отдельными механиками. Вместо этого — один универсальный инструмент в окне Круга:

- Поле «Корректировка ГМа»: число (может быть отрицательным) + короткий текстовый комментарий (необязательно).
- Применяется к итоговому балансу жетонов наравне с секторами и модификаторами.
- ГМ голосом называет число («+5 за успешный Ритуал», «-1 за разницу Кругов»), игрок вписывает его сам.
- Это же поле годится на будущее для любых ситуативных корректировок, которые не стоит зашивать в код.

## 9.1 Примерная Сложность (реализовано в v0.7)
Отдельный блок в правой колонке, живо считает по правилам из документа:
- Берутся все секторы Круга (только сторона Траты) с тиром > 0.
- Находятся два сектора с наивысшими тирами («Два Ключевых Направления»), их тиры складываются.
- Сумма сверяется с таблицей:

|Сумма двух высших тиров|Категория|Сложность|Откат|
|--:|---|---|---|
|0–1|Незначительная или Малая|без броска / 5|отсутствует / минимальный|
|2–3|Малая|10|≈1 Стресс|
|4–5|Средняя|15|≈2 Стресса|
|6–7|Сложная|20|≈3 Стресса|
|8|Невероятно сложная|25|≈4 Стресса|

Показывает не только категорию, но и разбивку по Путям внутри каждого из двух Ключевых Направлений (например, «Урон IV (Воплощение ×3, Усиление ×1)»), используя ту же логику подсчёта, что и в чат-карточке. Явно подписано как ориентир для игрока — финальную категорию всегда определяет ГМ (нарративный вес, особые условия по разделу «Определение сложности броска» документа). Эта же оценка добавляется в чат-карточку при сотворении.

## 9.2 Живое наблюдение ГМа за сборкой (реализовано в v0.13)

### Компоненты
- `scripts/gm-watch.js` — постоянный виджет (обычный `<div>`, добавлен в `document.body`, не Application и не привязан к какому-либо листу/окну), показывает список актуально открытых сборок. Виден только ГМу. Хранит `openBuilds: Map<actorId, {actorName, userId, state, updatedAt}>` в памяти клиента ГМа.
- `scripts/gm-viewer-app.js` (`FreeMagicGmViewer`) — `ApplicationV2`, открывается по клику на строку в виджете. Показывает live-состояние конкретного актора: секторы Круга/Докупки (только чтение), Модификаторы (редактируемо), Токены Путей + Максимум Цены (редактируемо).
- `scripts/modifiers.js` — общий список Модификаторов, вынесен из `circle-app.js`, чтобы окно наблюдения ГМа не дублировало его данные.

### Протокол по сокету (`module.free-magic`)
| action | Кто шлёт | Кто слушает | Назначение |
|---|---|---|---|
| `buildOpened` | Окно Круга при первом рендере | `gm-watch.js` | Добавить строку в виджет ГМа |
| `buildClosed` | Окно Круга при закрытии | `gm-watch.js` | Убрать строку из виджета, пометить открытое окно наблюдения как "сессия закрыта" |
| `buildStateUpdate` | Окно Круга при каждом пересчёте (throttle ~200мс) | `gm-watch.js`, открытое `FreeMagicGmViewer` для этого актора | Обновить отображаемые секторы/Докупку/Модификаторы/Намерение |
| `gmSetModifier` | `FreeMagicGmViewer` при клике по чекбоксу | Окно Круга ТОГО ЖЕ клиента, если оно открыто (см. `liveInstances`) | Применить переключение модификатора на живом состоянии игрока |

### Почему жетоны Путей и Модификаторы синхронизируются по-разному
- **Жетоны Путей / Максимум Цены** — персистентные данные (флаги актора). ГМ пишет напрямую через `paths.js` (`setManualPathPool`/`setPriceMax`), а клиент игрока подхватывает изменение через штатный хук Foundry `Hooks.on("updateActor", ...)`, зарегистрированный в `_onFirstRender` окна Круга — никакого отдельного сокет-канала для этого не нужно, раз это уже документ, а не эфемерное состояние.
- **Модификаторы (`modsOn`)** — чисто оперативное состояние конкретной сессии сборки, нигде не персистится. Для них нужен настоящий сокет-round-trip: `gmSetModifier` → клиент игрока (если у него открыт Круг этого актора, определяется через `liveInstances: Map<actorId, FreeMagicCircle>` — реестр открытых на ЭТОМ клиенте окон) применяет изменение и сам же разошлёт следующий `buildStateUpdate`, подтверждающий результат ГМу.

### Ограничения текущей версии
- Секторы самого Круга/Докупки в окне наблюдения — только для чтения, ГМ не может их поменять оттуда напрямую (только посмотреть).
- Если у ГМа нет активного подключения в момент, когда игрок открывает Круг — виджет не появится, пока ГМ не переподключится; ранее открытые сборки не теряются, пока продолжают транслироваться.

### ⚠ Известная проблема (найдено и исправлено в v0.14)
При тестировании v0.13 постоянный виджет ГМа не появился вообще ни разу. Причина — стандартное поведение сокетов Foundry: `game.socket.emit()` не доставляет событие самому отправителю. Все три уведомления (`buildOpened`/`buildClosed`/`buildStateUpdate`) в `circle-app.js` шли только через сокет — если Круг открывает сам ГМ (тестирует лично или ведёт NPC), в комнате из одного активного клиента событие уходит на сервер и рассылается «всем остальным», то есть никому. Исправлено: `gm-watch.js` теперь экспортирует `handleGmWatchMessage(data)` — общую точку обработки, которую дёргает и сокет-слушатель (для реального игрока на другом клиенте), и сам `circle-app.js` напрямую сразу после `emit()`, если отправитель — ГМ (`if (game.user.isGM) handleGmWatchMessage(data)`). Между двумя разными живыми клиентами всё уже работало и раньше — баг был виден только в сценарии сольного тестирования ГМом.

## 11. Ресурс Сцены (Элементы, Аспекты, Магический Фон v2)

Пересмотр раздела 6 под новую ключевую концепцию: помимо общего Магического Фона на сцене теперь существуют **Элементы** (общий пул на всех заклинателей этого Элемента на сцене) и вложенные в них **Аспекты** (под-Элементы со своим отдельным числовым значением). Всё это — части одной системы «Ресурс Сцены» с общим виджетом.

### 11.1 Модель данных

Два уровня хранения, по аналогии с уже отработанным разделением «мировые настройки vs флаг конкретной Сцены» (см. раздел 6):

**Мировой каталог** (`game.settings`, `scope: "world"`, редактируется редко, в вкладке «Каталог» GM Settings):
```js
{
  elements: {
    fire:  { id: "fire",  label: "Огонь",  icon: "...", tooltip: "..." , aspects: {
      ember: { id: "ember", label: "Тлеющий Уголь", icon: "...", tooltip: "..." }
    }},
    water: { id: "water", label: "Вода", icon: "...", tooltip: "...", aspects: {} },
    // ... земля, воздух, свет, тьма, дух, жизнь, время, пространство, космос
  }
}
```
Список Элементов фиксированный по замыслу (11 доменов + их Аспекты) — каталог даёт им иконку/тултип один раз на весь мир, а не пересоздаётся на каждой сцене.

**Флаг Сцены** (`scene.flags.free-magic.resource`) — какие из элементов каталога *активны на этой сцене* и их текущие значения:
```js
{
  background: { value: 32, max: 50, instability: 1 }, // instability — перманентный счётчик, не сбрасывается сам
  active: {
    fire:  { value: 8, max: 12 },
    ember: { value: 2, max: 4 } // Аспект — отдельная запись, родитель определяется каталогом
  }
}
```
Источник истины по «что вообще существует» (id/label/иконка/тултип) — каталог; источник истины по «сколько сейчас и активно ли на этой сцене» — флаг Сцены. Это то же расщепление ответственности, что уже используется между Items (запас Путей) и флагами (потрачено) в разделе 2.4.

### 11.2 Магический Фон v2 — перманентная Нестабильность

Отличие от раздела 6: раньше «замок Нестабильности» снимался (по максимуму или вручную ГМом). Теперь:
- Достижение 0 обнуляет `value` обратно до `max` **и** увеличивает `instability` на +1 — это уже не булев замок, а счётчик, который никогда не сбрасывается сам (только вручную ГМом, если вообще нужна такая кнопка — уточним).
- Статус для игроков вычисляется из **пары** `value/max` и `instability`, не только из процента:
  - `instability == 0` → обычная шкала: 70%+ Стабилен / 30–70% Риск Аномальности / <30% На Грани
  - `instability >= 1` → Фон **перманентно** «Нестабилен» независимо от текущего процента (само число может быть полным после сброса, но статус всё равно держит наихудшее состояние)
- ГМ всегда видит точное число + `instability`; игроки — только статусную строку (и точное число, если у умения выставлен флаг видимости — см. 11.4).

### 11.3 Базовое / Упрощённое отображение и встраивание в Круг

- **GM Settings** — `ApplicationV2` с двумя вкладками: «Каталог» (мировой, редко трогать) и «Эта сцена» (максимум Фона, чекбоксы «активен на сцене» по каждому Элементу/Аспекту из каталога + стартовые значения).
- **Базовое отображение** — самостоятельный виджет на сцене (аналог `gm-watch.js` по способу инъекции в DOM, но всегда виден игрокам, не только ГМу): строка Фона, затем строки активных Элементов, Аспекты — с отступом под родителем. Видимость точного числа — по флагу умения и по совпадению Элемента персонажа.
- **Упрощённое отображение** — тот же виджет, компакт-режим (иконка + число/статус мельче, только `+`/`-`), это и есть вид, который встраивается в окно Круга (4-й пункт из твоего списка) — отдельного пятого варианта верстки не делаем.
- И Базовый, и Упрощённый читают один и тот же стор (`scripts/scene-resource.js`), рендерят по-разному — не два независимых источника состояния.

### 11.4 Права на изменение и видимость

- Клик по Элементу/Аспекту: доступен ГМу всегда; игроку — если у него на актора выставлен флаг принадлежности к этому Элементу (`flags.free-magic.elements: ["fire", "ember"]`, туда же будем целиться при синхронизации с кастомным ресурсом в 11.5).
- Точное число Фона по умолчанию скрыто от игроков; конкретное умение/Домен-карта может нести флаг `flags.free-magic.revealsBackground: true`, который включает точное число в виджете для владельца этого предмета — реализуется как проверка «есть ли у актора хоть один Item с этим флагом», по той же схеме, что бонус-предметы Путей (раздел 7.1).
- Тултипы (по твоей просьбе) настраиваются в каталоге на каждый Элемент/Аспект отдельно + один общий тултип на Магический Фон.

### 11.5 Нестабильные Токены (ребрендинг Диких Токенов)

Механику из раздела 6 не меняем, меняем только область применения и имя:
- Клик по иконке Фона даёт до 3 Нестабильных Токенов за сборку — **если это сделано из окна Круга**, токен уходит в панель «Мои Токены Маны» как кисть (ровно то же самое, что сейчас делают Дикие Токены — непостоянный флаг, обнуляется при переоткрытии окна).
- Если клик сделан **вне** окна Круга (прямо на виджете сцены) — токен никуда не кладётся, это просто повод «засветить» рост Нестабильности игроку/ГМу и вручную применить какое-то умение по описанию — без автоматизации, по твоей формулировке «умениям, которым автоматизацию приделывать не надо».
- Переименование в коде: `wildToken` → `unstableToken` в `bank.js`/`paths.js`, обновить строки в UI.

### 11.6 Интеграция с Custom Resources Foundryborne (v0.19, после проверки)

Система даёт официальный механизм (см. [Module Builder Information → Custom Resources](https://github.com/Foundryborne/daggerheart/wiki/Module-Builder-Information#custom-resources)): в хуке `init` регистрируется `CONFIG.DH.RESOURCE.character.custom.<key> = { id, initial, max, label, images }` — после этого у персонажей появляется нативный трекер значения/максимума (как у Стресса/Брони), с кастомной иконкой.

Что это даёт нам и что нужно проверить перед тем, как закладывать архитектуру:
- **Регистрация статическая, на весь мир, при `init`.** Значит, ключи для регистрации берём из мирового каталога (раздел 11.1), а не пересоздаём на лету при каждой смене сцены — сам факт «Элемент существует» решается один раз при старте мира. Регистрацию можно перезапускать (`Hooks.callAll` / вызов `renderApplication` заново) при изменении каталога в GM Settings, но насколько чисто система подхватит это без релоада — нужно проверить на практике.
- **Неизвестно (нужно проверить на твоём инстансе), показывает ли система зарегистрированный кастомный ресурс на ВСЕХ листах персонажей одинаково, или это можно включать/выключать по конкретному актору.** Если показывает всем — получим на каждом листе счётчики всех 11 Элементов, что явно не то, что нужно (маг Огня не должен видеть у себя трекер Воды). Если так, обходим тем же приёмом, что уже применяли для кнопок на листе (раздел про DOM-инъекцию) — прячем через CSS/DOM строки ресурсов, Элемент которых не входит в `flags.free-magic.elements` актора.
- **Направление синхронизации — двустороннее:**
  - Ресурс Сцены → лист персонажа: когда виджет меняет `active.fire.value` на сцене, находим на сцене акторов с `flags.free-magic.elements` включающим `fire`, и пишем `actor.update({"system.resources.custom.fire.value": ...})`.
  - Лист персонажа → Ресурс Сцены: вешаем `Hooks.on("updateActor", ...)`, если изменился `system.resources.custom.<key>.value` — двигаем то же число во флаге текущей Сцены актора, чтобы игрок мог тратить Элемент прямо с листа (например, через нативную кнопку умения) и это тут же отражалось в общем пуле.
  - Нужна защита от зацикливания (сравнивать старое/новое значение перед тем как инициировать встречное обновление, как уже сделано для `gmSetModifier`/`buildStateUpdate` в раздел 9.2).
- Предлагаю сделать это отдельной, последней подверсией (v0.19) именно потому, что тут есть реальная неопределённость в поведении чужой системы — до трёх предыдущих версий (Базовое/Упрощённое отображение, Нестабильные токены) она никак не блокирует.

## 12. Тэги, Атрибуты Магии, Стойкость v2 и панель на Листе v2

### 12.1 Item-типы «Тэг» и «Атрибут Магии»

Два новых саб-тайпа Item, по той же схеме, что уже даёт систему Путей (раздел 2.1) — регистрируются как новый тип, не флаги поверх `feature`, потому что тебе нужно явно выбирать этот тип при создании предмета вручную.

**`free-magic.tag`** — минимальный саб-тайп: название, иконка, описание. Никакой встроенной логики — единственная цель существования отдельного типа - визуально отделить их от обычных Особенностей персонажа на листе и в панели (раздел 12.3). Ты создаёшь их сам и раскладываешь по Skill Tree как обычные предметы-дропы.

**`free-magic.attribute`** — поля:
- `tier` — enum: `base` (1★) / `proficiency` (2★) / `mastery` (3★). Фиксируется один раз при создании предмета — не переключается в рантайме (в отличие от старого плана раздела 2.2). Если нужен рост от Базового к Мастерству, ты просто кладёшь в дерево три раздельных Item одного и того же Атрибута с нарастающим тиром.
- `effect` / `costFormula` — как эффект отражается в Круге (стоимость в жетонах, даруемые токены, что угодно) — конкретные поля уточним, когда дойдём до v0.20, вероятно то же простое выражение, что было в старом плане `formula`.
- `scope` — `personal` (обычный Item, нужно, чтобы был у актора) / `base` (не кладётся на актора вообще, приходит только из мирового каталога GM Settings, см. 12.4) — на случай, если предпочтёшь держать «базовый набор» тоже как Items в специальном компендиуме, а не как отдельный список в настройках. Финальное решение — на v0.24, когда будем проектировать вкладку «Атрибуты» в GM Settings.

### 12.2 Магическая Стойкость v2

Второй кастомный ресурс актора (наравне с Ресурсом Элементов из раздела 11.6) — `CONFIG.DH.RESOURCE.character.custom.magicResistance`. Работает как Броня механически (кликабельные ячейки value/max на листе), но с другим значением:

- Трата ячейки Стойкости при получении заклинания на себя даёт выбор — **проигнорировать Урон от заклинания ИЛИ его Мистический Эффект** (то, что относится к нарративному Описанию заклинания, не к цифрам).
- v1 — вручную: цель сама кликает ячейку на своём листе (нативный трекер ресурса), выбор Урон/Эффект не автоматизирован — просто уговорились голосом/в чате, что именно игнорируется, аналогично тому, как раньше планировалась ручная трата Стойкости через Item (раздел 8). Автоматизация (кнопка в чат-карточке заклинания с явным выбором) — не блокирует базовую версию, переносится в «потом», как и списание Стойкости в старом плане.
- Прокачка `max` — Items типа `free-magic.attribute` могут нести бонус к максимуму Стойкости (тем же флаговым механизмом, что бонус-предметы Путей, раздел 7.1), либо просто вручную правится в GM Settings/на листе — решим на этапе реализации.

### 12.3 Боковая панель «Тэги и Атрибуты» на листе персонажа

Новая кнопка на шапке листа, тем же приёмом DOM-инъекции, что уже отработан для Панели Путей (раздел 7.1) — открывает выезжающую панель (или отдельное окошко, решим по месту) с тремя блоками:

1. **Тэги** — список всех `free-magic.tag`, которыми владеет актор.
2. **Атрибуты Магии от 2★** — все `free-magic.attribute` актора с `tier` = Освоение или Мастерство (Базовые, 1★, здесь не показываются — они по-прежнему участвуют в расчётах Круга, просто не загромождают эту сводную панель).
3. **Заклинательный Лимит** — число, читается как «за одну Активацию нельзя потратить Ресурса больше значения твоей Заклинательной Характеристики». Технически: сумма потраченных за одну сборку единиц Ресурса Элементов (раздел 11) сверяется с выбранной характеристикой актора.
4. **Резерв на Ресурс** — если в v0.19 выяснится, что нативные кастомные ресурсы Foundryborne нельзя избирательно скрывать по актору, эта же панель становится основным местом, где игрок видит свои Элементы/Аспекты/Стойкость — просто рендерим тот же виджет из раздела 11.3 внутри неё, вместо (или в дополнение к) нативным трекерам на самом листе.

**Заклинательная Характеристика — решено.** Подтягивается из подкласса актора, доступна как путь ролл-данных `@cast`. Технически читаем через `actor.getRollData()` (стандартный API Foundry/Foundryborne для формул) — `foundry.utils.getProperty(actor.getRollData(), "cast")` — и получаем нужное число напрямую, без отдельной мировой настройки или флага-переопределения: раз это уже приходит от подкласса на уровне системы, модулю не нужно ничего хранить самому, только читать значение в момент проверки Лимита. Если у актора вообще нет подкласса с `@cast` (например, NPC/адверсари) — обрабатываем как отсутствие Лимита (не показываем строку) либо как 0, уточним на этапе реализации.

### 12.4 Виджет Модификаторов в Круге — переезд на новые Item-типы

Меняется источник данных `scripts/modifiers.js` (раздел 9.2): вместо единого захардкоженного списка теперь два источника, объединяемых в один список при рендере:

- **Базовый набор** — задаётся в новой вкладке «Атрибуты» GM Settings (раздел 12.4.1 ниже), общий для всех персонажей независимо от того, есть ли у них соответствующий Item.
- **Личные** — все Items типа `free-magic.attribute` на акторе, вне зависимости от `tier` (Базовые тоже участвуют, ограничение 2★+ из раздела 12.3 касается только сводной панели, не самого Круга).

#### 12.4.1 Вкладка «Атрибуты» в GM Settings
- Список **базового набора** — Атрибуты, которые ГМ явно назначил «доступны всем», хранится в мировой настройке (не как Items на конкретном акторе — иначе пришлось бы дублировать на каждого).
- Список **персональных назначений** — таблица «Атрибут → какие актора/игроки видят его в Круге», для Атрибутов, которые не выданы как личный Item, но должны быть доступны точечно (например, тестовый доступ до того, как формально выдать предмет через Skill Tree).
- Это тот же паттерн «глобальный каталог + точечные исключения», что уже используется для Ресурса Элементов (мировой каталог, раздел 11.1) — переиспользуем ту же вкладочную структуру окна GM Settings, если технически удобно объединить оба каталога в одном окне с разными вкладками.

## 13. Вкладка «Игроки» в GM Settings — консолидация настроек по персонажу

Три параметра, которые сейчас (или по плану) разбросаны по разным местам, переезжают в одну вкладку окна GM Settings — таблица «персонаж → три поля», редактируется только ГМом:

1. **Элемент** — какой Элемент (из мирового каталога, раздел 11.1) закреплён за этим персонажем. Пишется в `actor.flags.free-magic.elements` (см. раздел 11.4) — именно этот флаг определяет, чьё числовое значение Ресурса виден персонажу в Базовом отображении виджета и какой ключ синхронизируется с кастомным ресурсом на листе (раздел 11.6).
2. **Объём Сосуда** — переименование существующего «Максимум Цены» (`priceMax`, флаг актора, `paths.js`): сколько Стресса персонаж может вложить в модификатор Цена за одну сборку. Хранение и логика клампа не меняются (`getPriceMax`/`setPriceMax`, `PRICE_MAX_CEILING`) — меняется только то, ГДЕ это редактируется.
3. **Заклинательный Лимит** — по умолчанию подтягивается автоматически из `@cast` (раздел 12.3, `actor.getRollData()`), но теперь так же, как раньше произошло с Максимумом Цены (см. v0.10.2 в дорожной карте — «сам верхний предел» вместо жёсткого расчёта), появляется возможность у ГМа вручную переопределить конкретному персонажу число, если авто-расчёт почему-то не подходит (нет `@cast`, гомбрю-исключение и т.п.). Переопределение — отдельный actor-флаг (например, `free-magic.spellcastLimitOverride`), который, если задан, побеждает автоматическое значение из `@cast`.

**Убирается из окна Круга:** поле «Максимум Цены» (`circle-app.js`, строки с `fm-purchase-limit-input` — ввод прямо на странице Докупки) удаляется как редактируемый инпут. Само значение по-прежнему используется в Круге для расчёта эффективного максимума (`effectiveMax`), просто больше не редактируется оттуда — только читается. Окно живого наблюдения ГМа (`gm-viewer-app.js`) с полем `fm-gmv-price-input` — отдельный самостоятельный инструмент ГМа (наблюдение за конкретной активной сборкой в реальном времени), не «Окно Сборки» в смысле этого решения, поэтому по умолчанию не трогаем; если после появления вкладки «Игроки» оно станет дублирующим — уберём отдельным пунктом по факту, не сейчас.

Технически вкладка «Игроки» — простой список акторов-игроков (`game.actors.filter(a => a.hasPlayerOwner)` или похожий фильтр, уточним при реализации) с тремя полями в ряд на каждого; сохранение — прямые вызовы уже существующих `setPriceMax`/будущего аналога для Элемента и Лимита, никакого нового формата хранения не вводится, только новое место редактирования.
